# RFC 0034：会话优先的客户端与资源感知选机

> 编号：0034 · 状态：已采纳 · 创建：2026-11-24
> 相关：[RFC 0030](0030-network-acp-and-shared-workspaces.md)、[RFC 0033](0033-cross-provider-async-session-control.md)

## 背景

跨主机侧栏已经按会话组织。新建会话仍默认绑定当前主机或列表第一台。跨机派发原先要求 Agent 在每次创建前提供 peer，对当前负载缺乏统一判断。

## 目标

- 将会话优先的工作区确立为原生客户端规范。主机与 provider 在会话和创建界面显示为执行资源。
- 用户保留执行主机选择权。默认建议依据当前资源与准入，适用于新会话及任意深度的 ACP 派发。

## 设计

评分和资源新鲜度见[生效规范](../docs/spec/network-acp-and-collaboration.md#13-基于资源的默认选机)。Rust Core 查询已连接工作区的资源事实，原生窗口获取一次建议并保留用户选定的主机。Rust Node 为 ACP 网关提供同一算法的只读分数。网关经现有 v2 认证和工作区校验后公开分数。调用方从自身可信 peer 清单选择目标并只发起一次创建。

资源分数表示观测时的容量。目标主机保有准入与生命周期权威。节点升级或采样失效时，已支持的显式选机路径继续可用。每轮派发保留实际直接父会话，并返回后续命令使用的 peer。

## 对 SPEC 的影响

- [客户端规范](../docs/spec/client-and-media.md#41-共同规则)约束工作区导航和新建会话选择。
- [网络 ACP 规范](../docs/spec/network-acp-and-collaboration.md)记录候选、评分、超时和显式选择规则。

## 验收

验证在线与离线、过期样本、内存准入和 CPU 饱和的排序边界。ACP 夹具覆盖真实路径限制、嵌套父引用、手动指定优先、选择后失败时无重发。真实主机负载与原生设备交互按对应环境分别验收。

2026-11-24 的本地验收包含 Rust 与 Bun 回归、隔离 Unix Socket 和 ACP CLI/MCP 夹具、Android 构建与单测、Windows 交叉构建，以及 macOS UniFFI 绑定生成。真实跨机负载与原生设备安装留待对应环境验收。
