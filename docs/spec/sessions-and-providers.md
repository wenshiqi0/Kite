# 会话图谱、Provider 接入与交互规范

## 1. 会话图谱与核心模型（RFC 0027）

- **领域概念**：`Conversation` 是持久会话记录；`LiveSession` 是单个会话的运行态对象；`Item` 由有序的类型化 `Block` 组成；`Thread` 是有序、可不连续的 Item 编组；`Reference` 区分活引用与快照；`Origin` 记录分叉来源；`Subscription` 是本机阅读状态。
- **会话键唯一性**：所有会话作用域的键必须从 `ConversationKey` 派生，不得另行拼接字符串。
- **状态替换原则**：切换会话必须整体替换 `LiveSession` 运行态对象，不得逐字段手动清零。
- **类型化内容与信封**：消息正文必须以类型化 `Block` 表达；provider 历史中的 Kite 自有结构只能经统一 envelope 模块编解码，信封无法无损表示的发送组合必须拒绝而非静默丢弃。
- **引用与分叉**：活引用仅存在于 Kite 目录叠加层；进入 provider 的引用必须是带来源标记的快照。分叉能力按 provider 真实公布呈现（Codex 按轮、Claude 整会话、ACP 快照拷贝），无能力时不显示入口。
- **本机订阅状态**：阅读状态、置顶、静音归本机 `Subscription`，不回写主机目录。`conversation_revision` 仅是进程内展示增量版本，不得持久化为阅读游标；阅读游标必须基于稳定的 provider Item ID、内容摘要及已验证通知位置。
- **原始历史只读保留**：任何情况下不得移动或改写 provider 的原始历史文件。

## 2. 多主机工作区、目录排序与连接恢复

### 2.1 多主机并行工作区

- 客户端允许同时连接多台主机。Rust `ClientCore` 按主机 ID 隔离工作区，各主机的连接、重试、聊天同步、资源和通知轮询独立运行；本地存储与设备私钥共享并串行写入。
- 切换选中主机只改变当前工作区并关闭原桌面媒体串流，保留原主机的连接与会话选中状态。
- 显式断开或修改主机配置仅取消目标主机的任务；“断开全部”清除全部连接意图。
- 会话列表与操作命令必须显式携带 `host_id` 与 `session_id`，异步执行不得随界面当前选中项漂移目标。
- 会话排序按主机持久化，默认按创建时间从新到旧，同时支持从旧到新、最近活动和标题；时间相同时以会话 ID 稳定兜底，排序不改变当前选中会话。归档或删除当前选中项后，按操作前顺序选下一条可用会话（末尾选前一条）；操作非选中项不改变当前选中。

### 2.2 自动重连与恢复边界

- 显式连接意图持久化全部目标。遇到临时网络/SSH 故障时，进入可取消的指数退避自动重连（`1 / 2 / 4 / 8 / 16 / 30` 秒）；无网络时等待，网络切换或前台恢复触发有界只读探测。
- 认证拒绝、未知或变化的主机指纹不得自动放行。
- 重连恢复**只重新连接并观察原会话**，绝不自动创建新会话、恢复 owner，或重放用户消息、回答、审批与桌面输入。
- 断线立即退出桌面操作接管；视频恢复后强制回到只看模式。
- 新建会话尚未落盘 provider 历史文件时处于初始化等待状态，不得误报同步失败或以空记录覆盖已有缓存。Chat 视图不自动退回终端原文，终端诊断仅由用户显式打开。

## 3. 会话与 Owner 生命周期（RFC 0007 / 0020）

- **主机会话目录**：使用原子修订号写入与单会话恢复租约锁；记录、运行进程与客户端连接三者生命周期独立。
- **统一资源释放协议**：资源释放是托管 harness 的统一能力（`HarnessLifecycle`），客户端与自动归档复用同一结构化命令（`sessions-release-archived`）。
- **归档回收策略**：
  - 归档保留正在执行中的任务，任务结束并确认上下文已落盘可恢复后，才回收 TUI、app-server / owner 及其本地工具子进程；
  - 归档且空闲、仅被归档记录共享的 owner 在核验非活跃、未暂停、无活跃别名且存在唯一非空可恢复上下文后立即回收；
  - 未归档会话**不因闲置超时回收**；
  - 释放保留原会话引用与 provider 原始历史，后续继续会话按原 provider thread/session ID 恢复唯一 owner。
- **显式删除会话**：活动和归档列表均可直接删除，命令绑定目标主机与会话 ID。删除授权立即终止该会话任务；主机在目录与 owner 锁内核验身份、排除被其他活跃会话共享的 owner，释放受管进程及其本地子进程并确认退出后，才移除 Kite 目录记录。私有删除标记防止过期写入或发现结果复活记录，且不保存对话正文；provider 原始历史保持原位。

## 4. Provider 目录与具体实现约束

新增或排查 harness/provider 接入细节时，按需阅读 [Agent Harness 内部接入规范](../development/harness-integration.md)。

### 4.1 统一目录与能力对齐（RFC 0021 / 0023）

- 主机探测并发布经过验证的可用 provider 目录，Rust 将其转换为能力快照驱动客户端选项；未验证可用的 provider 不在新建入口展示。
- 原生模型列表、思考强度、视觉/附件模态与权限配置必须从各自真实后端查询，并贯通同一客户端控件（harness 采用下拉选择器）；不得把适配器缺口伪装成 provider 原生不支持。
- **受管会话系统提示词与 Kite MCP 注入（[RFC 0035](../../rfcs/0035-provider-system-prompt-and-mcp.md)）**：Kite 在启动或恢复受管模型会话时，通过各 provider 原生非破坏通道统一追加全局 Kite 系统提示词（子任务派发走 `kite acp` v2 / `kite_session_*`、宿主机与桌面走 Kite、澄清优先使用结构化提问工具）并注入会话级 `kite` / `kite_acp` MCP 服务（显式透传 `KITE_SESSION_ID`）；只读探针不预加载 MCP，不得覆写用户全局配置或污染可见聊天历史。
- 当前已注册 provider 分为两类（见 [packages/protocol/src/index.ts](../../packages/protocol/src/index.ts)）：
  - **结构化聊天 provider（`CHAT_PROVIDERS`）**：`codex`、`dsh`、`ply`、`antigravity`
  - **终端型 provider**：`claude`（属于 `PROVIDERS`，未连接时明确显示待连接状态）

### 4.2 各 Provider 关键规则

| Provider | 协议与机制 | 专项规则 |
| --- | --- | --- |
| **Codex** | 持久 `app-server v2`，同一 pane 的 TUI 与客户端共享同一 owner 和 thread ID | 1. **速度档位**：模型目录公布 `serviceTiers` 加速档位时同时提供标准速度；按主机和会话持久化，随下一条消息提交，切换模型若不支持则回退标准速度。<br>2. **显式 Skill**：按 `cwd` 经 `skills/list` 查询，Rust 持有每条消息选择；Android 加号菜单选入可移除标签，发送成功清除、失败保留，不改全局 skill 配置。<br>3. **套餐额度**：独立于聊天只读查询，客户端销毁即取消；不保存账户凭据，不凭缺失字段猜测余额，不以重置时间推断发送权限。<br>4. **原生历史 DB**：无 JSONL 时通过主机能力 `historyNativeApi` 只读原生历史数据库，在私有目录维护投影；推理条目不进入正文。<br>5. **关联任务**：以平层“关联任务”列表展示真实后代（不画多级树）；通过只读 `thread/list` 获取元数据与事实，Rust 统一裁定状态；点击只读查看并复用主聊天条目渲染组件，不创建独立终端或改变原会话引用。 |
| **DSH** | 显式环境变量启用，经鉴权模型健康探测与原生协议连接（[RFC 0021](../../rfcs/0021-dsh-provider.md)） | 模型列表与健康探测结果取交集校验；内部规范化到统一聊天事件，不向 DSH 发送 Codex 私有 RPC。 |
| **Ply** | 独立 ACP v1 插件 `ply acp`（[RFC 0025](../../rfcs/0025-ply-acp.md)） | 不保留旧 MCP 协议回退；恢复仅保存原生 `sessionId`，私有快照留存 Ply；支持模型、思考强度、工具事件、权限与取消。 |
| **Antigravity** | 显式启用 `agy acp`（[RFC 0032](../../rfcs/0032-antigravity-acp.md)） | 以已鉴权的 `session/list` 为发现依据；持久保存原生 ID 冷启动恢复，归档释放前确认原生上下文可查询。<br>权限面板提供独立 `tool_permission`（`default` / `turbo` 对应 `--dangerously-skip-permissions`），随下一条消息生效；切换时等旧进程退出并以同一原生 `sessionId` 恢复，不批准已挂起审批，不改全局配置。 |
| **Claude** | Herdr 终端型集成与 `--resume` 路径 | 历史读取为有界尾部，不宣称具备与 Codex 同等的结构化历史/模型设置能力；未连接时明确展示待连接状态。 |

## 5. 会话权限设置与可读审批（RFC 0026）

- 会话权限设置放在模型浮层中，只展示后端真实公布或本机管理约束（如 Codex `configRequirements/read`）允许的参数，按主机与会话保存，随下一条消息生效。
- 排队消息各自保留提交时的权限设置，新策略不回溯污染前一轮，也不自动批准已挂起审批。
- 权限应答查询**统一实时 agent 清单**（涵盖 Herdr 终端与独立 owner 托管的 DSH / Ply / Antigravity），校验主机、会话、请求与选项身份，不重发应答。
- 审批卡必须展示具体操作类型、完整命令、实际工作目录和结构化参数，明确区分“允许一次”与“拒绝”；“允许一次”不修改会话策略。

## 6. 聊天交互、展示与稳定性

### 6.1 富文本与特殊信封渲染（RFC 0008）

- 聊天条目以类型化 `Item/Block` 推送；所有发送者复用同一套内容块、Markdown（Android 使用 Markwon）、附件预览与错误展示组件；外层气泡保留左右布局与按发送者区分的背景/内边距。
- 附件二进制按需经附件通道下载并缓存，不塞入快照或增量正文；只有纯工具 Item 进入折叠工具组。
- Codex 完整全局 `AGENTS.md` 注入信封在客户端折叠为单行“已加载全局指令”，原始对话不变。
- 完整 Skill 指令信封由 Rust 投影为只读 `SkillContext` 块，Android/macOS 默认折叠为“Skill 指令”卡片（展开显示来源路径和 Markdown），不使用用户消息样式或“你”署名。
- 主聊天与关联子任务详情必须复用同一个条目渲染组件，只读查看通过能力参数限制交互。

### 6.2 输入区、中断与异步问题（RFC 0009）

- Android 输入区不提供语音识别入口。空草稿且 agent 工作中显示中断按钮；草稿含文字、附件或 Skill 时可继续发送追加指令。中断经 Rust 校验当前会话取消活跃 turn（终端型使用已验证 Escape），保留会话和草稿，与进程暂停独立。
- 阻塞问题通过原 RPC 应答；异步问题通过历史体 v2 独立传输控制记录，Rust 关联真实 call ID 决定待答状态并通过同线程 TUI 回答信封提交。
- 答题卡/弹层可随时关闭并保留草稿，不隐藏普通输入区；用户显式发送普通新消息时，Rust 先对仍待答的阻塞问题回复空 answers 跳过，再发送新消息；仅关闭界面不提交也不跳过。

### 6.3 完整会话与界面稳定性（RFC 0013）

- 长会话由 Rust 管理完整消息、持久缓存与独立后台回填；冷启动先展示最新页，状态快照不携带正文，原生按 `conversation_revision` 增量维护展示镜像并采用虚拟渲染，滚动不得触发历史网络请求或淘汰逻辑消息。
- 传输断开或重试时，Rust 取消同步并使待答/输入授权失效，但保留已保存会话的消息对象、版本与展示身份；同一会话全量同步复用未变行和工具分组标识。
- Android 连接状态使用固定高度单一提示条，错误详情移入诊断弹窗；视口几何与底部锚点在测量阶段统一处理，阅读历史时保持原有阅读锚点（不受连接提示、关联任务、输入区及键盘高度变化扰动）。
