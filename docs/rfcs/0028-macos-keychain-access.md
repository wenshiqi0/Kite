# RFC 0028：Mac 开发版的持久密钥访问身份

> 状态：已实现并通过跨构建无交互验证 · 2026-11-02

用户要求一次性完成授权，应用更新不再反复弹窗。临时签名按 cdhash 识别应用；本机非 Apple 签发证书虽然能稳定 designated requirement，现代登录钥匙串的 partition ID 仍按 cdhash 变化。因此本机开发版使用固定证书签名，并将钥匙串读写交给只安装一次的原生组件。

组件位于用户私有 Application Support 目录，每次请求按需启动，不注册后台服务、不监听网络。应用正常构建不得覆盖组件。组件只操作 Kite 服务内 `ssh-ed25519` 和 `sunshine-identity` 两个条目，保留原有数据。显式设置逐条进行无交互检查，仅为尚未授权的条目请求系统“始终允许”，由系统持久化组件信任和固定 cdhash；不由应用重写 ACL 或放宽为全部应用可访问。已可读取的条目跳过授权。

读写请求必须来自签名有效、bundle ID 为 `io.github.wenshiqi0.kite.mac` 且叶证书符合安装时固定证书的直接父进程。参数只传操作与条目名；秘密通过私有 stdin/stdout 管道传递，限制为 64 KiB，不写日志或临时文件。调用方同样核验组件的签名。普通读写禁用授权 UI，初始化失败明确返回错误，不自动重建密钥或回退到临时签名/直接读取。

Rust 的 SecretStore 接口、现有 SSH/配对身份和服务端协议均不改变。未来如需升级组件或轮换证书，须显式执行独立设置，不把授权变更混入每次应用构建。
