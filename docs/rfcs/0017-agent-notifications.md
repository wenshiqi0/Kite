# RFC 0017：agent 通知与移动端会话回访

> 状态：已采纳，实施中 · 2026-11-01

用户要求打通通知并回到移动端接收。基础链路为主机产生持久事件、手机接收并去重、Android 系统展示、点击回到正确主机/会话。历史、主机信任、设备身份和配对保持原格式；新增独立通知文档和接口，FFI 与绑定同次生成。

Rust 领域层定义完成、需要处理、异步提问和失败事件及稳定身份。Kite Node 独立观察主机上的会话，不依赖手机正在浏览哪个会话；事件日志、观察检查点和递增游标存于用户私有目录，原子写入并有界保留。不记录终端或模型消息正文。只在真实状态转换时通知；启动时的普通空闲状态不等于完成，重连不能重复通知。主机读取失败不等于 agent 失败。

移动端 Rust Core 保存接收游标和有界通知收件箱。原生负责权限、通知频道、前台/锁屏策略和系统 PendingIntent；事件传输、身份、去重、读取状态与目标验证归 Core。点击仅导航到验证过的已保存主机与实际会话，不自动回答、审批、恢复归档或执行模型操作。应用初始化、连接/信任和会话读取完成之前保留导航目标，不能落到错误主机。

Android 将连接常驻通知与 agent 提醒分频道；默认锁屏只显示通用提示。用户当前正在阅读的会话不重复弹系统通知，其他会话和后台/PiP 的待处理事件可提醒。提供开关和明确的系统权限入口，不在每次启动反复申请。网络连接服务使用合适的前台类型，媒体播放只在实际串流时使用，不能用无声播放伪装常驻。

保持后台连接的通知与进程被系统回收后的系统推送分别验收。后者依赖实际系统推送配置；当前尚无 Firebase/OEM 推送凭据，不得以 SSH 常驻通知冒充已经打通进程回收后的推送。已实现 FCM HTTP v1 高优先级数据消息传输与原生消息服务，使用稳定 AndroidConfig；AndroidConfigV2 当前为预览版。客户端公开配置经 CI 变量生成资源，发送凭据仅保留主机私有文件。真实项目、可用 Google Play 服务与实际手机投递仍是部署验收前置，详见 [配置和验收](../notifications.md)。强制停止应用、禁止通知和网络不可达等情况分别记录。

验收覆盖主机独立产生日志、状态转换/去重/重启恢复、手机后台接收、权限拒绝、锁屏隐私、实际系统通知点击、冷/热启动定位不同主机与会话、旧事件/删除会话及视频/聊天状态保留。可控测试实例和模型回访会话必须独立，结束时只清理测试资源。
