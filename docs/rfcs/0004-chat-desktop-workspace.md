# RFC 0004：聊天主界面与多形态桌面

> 编号：0004 · 状态：已实现（Android Alpha 2） · 创建：2026-10-29
> 产品依据：[原稿与确认记录](../product/2026-10-29/README.md)

## 已确认的产品行为

以 agent 聊天为主界面，保留固定输入区、身份与真实工作状态。桌面支持可拖浮窗、边缘收纳、上下分屏、全屏以及离开 App 后的 Android 系统画中画。全屏默认观看，观看手势只做本地缩放和平移；显式接管才发送远端输入。用户已确认接管不自动暂停 agent；暂停是独立操作，覆盖第三张原稿中“接管即暂停”的文案。

## 分层和数据

- 落实 SPEC 已规划的 `kite-agent`，依赖 `kite-ssh` / `kite-herdr`，负责归一化真实会话记录、工具调用、待处理终端选择及独立进程暂停。
- herdr 0.9.5 的 `agent.read` 返回终端文本；`agent.list` / `agent.get` 提供 `agent_session`（kind 为 id / path）。根据对应会话读取 Claude / Codex 记录，限制文件与响应大小，不扫描无关会话内容。无法结构化的内容明确显示为终端输出。
- 审批卡来自正在阻塞的终端选择，保留原始请求和实际选项。响应前重新核对 agent、当前状态及请求摘要，拒绝过期操作；通过既有 `agent.send_keys` 提交用户选择，不执行产品稿中的示例命令。
- 暂停操作根据 `pane.process_info` 提供的前台进程组核实所有者、进程身份与启动时间，显式停止 / 恢复该 agent 的进程组；与桌面接管状态完全分离。无法核实时返回明确失败。
- 聊天、工具、审批、暂停与连接状态由 Rust Core 持有，经同次生成的 FFI 快照交给原生层。布局、拖动位置、分屏比例、本地视口缩放和触控板模式由 Kotlin 负责。

## Android 呈现与生命周期

- 聊天列表使用真实消息身份，工具卡可展开；computer 类型工具可打开桌面。
- 只有一条媒体会话和一个原生视频目标。浮窗、分屏和全屏优先移动 / 调整同一视频平面，避免为布局切换重建配对与解码器。
- 默认保留源桌面分辨率，并与手机视口适配分离。观看模式缩放 / 平移不发输入；接管模式支持直接操作和触控板、键盘修饰键及显式粘贴。
- 使用系统 PiP API，配置 Activity 的 PiP 和布局变化处理；PiP 隐藏聊天与控件，保留视频和连接，并释放已按下的远端输入。返回 App 恢复先前布局。
- 主机配置和设备身份移到可访问的设置 / 主机入口；保留已经批准的主机、信任和密钥迁移，不新增旧 FFI 兼容入口。

## 验收

离线验证会话归一化、工具结果关联、审批失效和进程身份校验。Android 实际验证聊天 / 工具 / 选择展示，浮窗拖动与收纳，分屏调整，全屏默认观看，接管不暂停 agent，源分辨率不随布局变化，缩放与输入映射，以及系统 PiP 往返。真实 agent 数据与受控测试夹具分别标注，不把编译或截图当作全部运行验收。通过 CI 构建并发布下一个 Alpha。
