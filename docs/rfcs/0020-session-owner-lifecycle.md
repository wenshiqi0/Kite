# RFC 0020：归档会话资源释放与按需恢复

> 编号：0020 · 状态：已实现 · 创建：2026-11-02
> 相关：RFC 0007（修订归档后的进程生命周期）、RFC 0014、RFC 0018

## 背景

归档目前只修改会话索引，完成的 Codex TUI、独立 app-server 和 MCP 子进程仍然驻留。wen.linux 的 15 个已归档会话回收后，物理内存用量由约 18 GiB 降到约 8 GiB。当前约定修订为：只释放已归档会话，未归档会话不能因闲置超时而退出；释放是各 harness 必须提供的统一协议能力。

## 目标

- 已归档会话在任务结束、上下文落盘后释放运行进程。
- 未归档会话无论闲置多久都不自动退出。
- 客户端已归档列表提供“释放后台进程”，CLI 提供 `kite sessions release-archived`，共用主机命令并返回释放、保留和失败数量。
- 保留 provider thread、完整历史、会话记录和可复用的 shell pane。继续会话使用原 thread ID。

## 设计

`kite-app::host_node::lifecycle` 在主机独立运行，每 30 秒检查一次。Rust 只选择已归档、空闲且上下文持久化的候选。目录写入和会话状态读取唤醒扫描，所以已完成会话归档后无需等待下一次周期。所有托管 harness 实现统一 `HarnessLifecycle`：只读快照、owner 租约、共享 owner 判定和资源释放。Codex、DSH、Ply 实现该协议；外部终端没有受管释放能力时不推测进程身份。Linux 适配器执行自身平台机制，不把 provider 分支放进客户端。

活动时间取显式继续/恢复时间、owner 启动时间和原始 provider 历史的修改时间。普通发现和只读 RPC 不更新活动时间。检查实际 app-server 的全部已加载线程，并结合 Herdr 识别的前台进程；执行中、等待审批、暂停、未知、未落盘和共享 owner 均保留。

执行回收时复用 `session-open` 的会话锁和 owner 锁，再次核对目录记录、provider 引用、PID/start ticks、活动指纹和实时空闲状态。先向核验过的闲置 TUI 发送 SIGTERM，再次检查 owner，最后委托 harness 适配器释放受管 cgroup 中的 owner 及其本地子进程；非受管 Codex owner 仅在核对独立进程组后退出。暂停的 TUI 保留。退出通过进程信号执行，避免把 `/quit` 拼进未提交的输入草稿。只退出远程 TUI 不会释放其持久 app-server，因此必须执行两步。回收不删除 provider 文件，不改变归档状态，不重放消息或工具操作。

Node `status.sessionLifecycle` 暴露 `archivedOnly=true`、扫描间隔、最近成功扫描时间和回收数量，不再暴露闲置期限。手动命令和自动扫描串行化，DSH/Ply 的输入和释放共用 owner 租约。最终释放期间持有目录锁，阻止并发解除归档或新增共享引用越过判定；归档进程的文件缓存按自身 cgroup 定向回收，禁止主动交换活跃堆内存。升级与扫描共用 observation gate，旧代次进入 draining 后不再执行回收。

## 显式删除（2026-11-03）

活动列表、归档列表和当前会话菜单均提供“删除会话”，无需先归档。原生确认框展示目标会话名，并说明会立即停止后台任务、释放资源及移除 Kite 记录和本机缓存；取消不发命令。Rust 校验主机身份，序列化用户操作并管理缓存、连接及下一条会话选择。

主机 `session-delete` 复用会话、owner 和目录锁。删除是用户显式终止指令，不使用自动归档的空闲或落盘门槛；已核验归属的受管进程无需先完成当前任务。Codex 验证独立 app-server、原生线程及 TUI；DSH/Ply 验证持有者的 sessionId、PID/start ticks 与专属 cgroup；Claude 只停止已验证的专属受管 shell scope。共享 owner、变化的身份、无法证明归属的活动终端或未退出的进程会返回失败并保留记录，不能误报删除成功。

主机确认 owner 及 cgroup 工具子进程退出后才移除目录条目，并原子保存不含聊天内容的 ID/引用摘要删除标记。目录读取与 CAS 写入都过滤标记，防止在删除前已取得列表的其他客户端重新导入。客户端删除持久聊天缓存、内存历史、附件及 Skill 草稿和持有的聊天连接；选择另一条活动记录或清空工作区，不自动恢复任务。provider 原始历史不移动或删除。

## 备选方案

仅关闭客户端不能释放持久 owner。归档时直接终止任务会丢失正在执行的工作。按状态轮询时间保活会使连接中的闲置会话永不过期。

## 对 SPEC 的影响

归档继续保留正在运行的任务，任务结束保存上下文后释放；移除未归档会话的一小时闲置回收，增加统一 harness 释放能力与客户端命令。原始历史和按原 thread 恢复的要求保持适用。

## 验证

覆盖未归档会话永不超时、统一客户端命令、DSH/Ply 协议与恢复上下文、只读轮询、重新活动、进行中的后台线程、未落盘上下文、PID 复用、并发解除归档、共享 owner、TUI 断开后的新活动，以及回收后原 thread 的恢复。主机升级使用现有兼容热交接流程。
