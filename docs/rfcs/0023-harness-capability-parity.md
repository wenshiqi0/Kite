# RFC 0023：Harness 原生能力对齐与统一选择入口

> 状态：已采纳 · 2026-11-02

用户要求恢复 DSH 的模型选择、原生视觉和思考强度，接入已支持 Linux 的 Ply，并统一为下拉选择。不能把适配缺失宣称为 native 不支持。

- 统一使用真实模型目录、逐模型输入模态及思考选项，能力在 native 适配层归一化后由 Rust/FFI 发布，原生客户端不按品牌裁剪。
- DSH 采用 ACP 会话/模型/思考/图像/权限/取消/持久恢复接口；补充目录桥接只读取其 LLM 服务，不维护第二套模型事实。连接级图像协商必要时在空闲时重新协商并恢复同一 native 会话，不能悄悄降为图片文件路径。
- Ply 使用 Linux 原生运行时及原生插件接口，扩展可信宿主调用以接收模型选择、图像、持久上下文和审批，不复制模型执行循环，不允许模型自行修改凭据或批准权限。
- Codex 和新接入使用统一模型与输入能力驱动控件；Claude 当前仍走原有 Herdr 文本/终端路径，不把未接入的结构化设置伪装成已支持；真实缺少的 native 接口、运行时不可用和未接入必须分别记录。额度缺失不伪装成零或其他产品的额度。
- 运行中追加文本采用 DSH 原生 steering；使用私有进程内桥接调用 native inbox，不并发发出 ACP prompt RPC。其他补充输入由唯一 owner 持久排队，关闭竞态不丢输入，取消清除待运行项。
- 四种 provider 的目录与原生会话能力使用 `harnessApi=2`；客户端和 Node 同版交付。旧版闭合目录不能误读新增 provider，Node API 1、backend protocol 5、resource API 1 和会话生命周期接口保留。连接旧 SDK 会话时先安全迁移空闲 owner，活跃任务保持原样，结束后再重连。
- Harness 下拉框只显示当前主机验证可用的选项；模型与思考为独立选择，视觉由当前模型决定。持久会话及并行主机功能在升级时保留。

验收覆盖真实目录、模型和思考切换、原生图像输入、工具/审批、取消、重连，以及旧数据和主机接口保留；用夹具验证协议和拒绝路径，用自有会话验证真实模型与原生 UI。
