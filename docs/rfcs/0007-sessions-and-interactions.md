# RFC 0007：会话记录、模型提问与工作过程

> 状态：已实现（Android Alpha 7） · 2026-10-30

用户要求工具调用合并折叠，会话可新建、记录、继续回复、归档，并能选择 Codex / Claude；同时补齐回答模型问题的界面和发送后的思考动画。继续使用已经确认的升级边界：保留历史、设备身份、主机信任和配对，FFI 同次生成，不维护旧聊天入口。

- 记录与运行进程分离：Rust 会话领域模型保存提供方、provider 会话引用、标题、工作目录、最近预览和归档状态。主机私有目录保存带修订号的会话索引；写入使用锁与 compare-and-swap，避免不同手机覆盖归档状态。原始 provider 历史保持原位。手机缓存最近记录，断开后仍能查看。
- 归档是列表整理，保留记录和后台任务；已归档记录可以查看，恢复后继续回复。继续会话优先复用同一 provider thread 的活跃 pane；需要恢复终端时，在主机单会话锁内复用已有 app-server，禁止建立第二个线程所有者。主机辅助程序只负责私有存储、租约和终端启动等 Linux 原子操作，Rust 决定用户命令、会话选择、缓存与快照。
- 新建会话明确选择 Codex / Claude。提供方随记录保存。Codex 实际连接与验收；Claude 可以保存待连接会话，并有独立的连接入口和适配边界，本次不主动连接真实 Claude，不生成模拟回复。
- 模型提问与执行审批分开。真实请求提供题干、选项和自由文本时，原生显示可提交的回答卡；响应核对主机、会话和请求身份。不把普通聊天输入当作执行授权，也不把回答一律禁用。可识别的终端交互沿用真实按键；未知交互提供真实终端入口。
- Rust 持有发送已接受、思考、执行工具、等待用户和回复等阶段，原生显示阶段提示和动画。提交时立即有反馈，完成、失败、断开或等待用户时停止思考动画。该动画不展示隐藏推理内容。
- Rust 标注公开的中间进度文本；Android 将连续工具与这些进度合并成默认折叠的工作过程，最终回复和用户消息独立显示。展开后内部列表有高度上限，并保留每次调用详情、失败和桌面入口。新增调用与结果更新不改变已有分组身份。

依据：[Codex app-server 官方说明](https://learn.chatgpt.com/docs/app-server)。Kite 的逻辑归档不调用会移动 provider 日志的 `thread/archive`。
