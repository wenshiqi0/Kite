# RFC 0011：桌面下方触控板与紧凑鼠标控件

> 状态：已实现，Alpha 12 · 2026-10-30

## 问题与证据

Alpha 11 的输入链路已通过功能验证，但用户实际使用反馈：控件过大，收起态仍显笨重，拖动受限，竖屏分屏几乎被控件占满。功能验收不代表手机上的空间利用和手感已经被接受。

现有代码可以定位到以下布局问题：

- [VirtualMouse.kt](../../android/app/src/main/java/io/github/wenshiqi0/kite/ui/VirtualMouse.kt)：展开固定为 170×162dp，收起为 46×46dp；只有展开态 32dp 高标题支持拖动。收起态只能点按，小视口中点按会进入全屏。
- [KiteWorkspace.kt](../../android/app/src/main/java/io/github/wenshiqi0/kite/ui/KiteWorkspace.kt)：鼠标控件放在视频框内，父容器裁剪；位置范围按视频宽高计算。分屏同时占用视频区、36dp 控制行和18dp分隔条。
- 360dp 宽的 16:9 全幅桌面仅高 202.5dp，162dp 鼠标面板高度约为画面高度的80%。这是尺寸推算，不是对用户手机进行的测量。

用户补充的 UU 展开/收起截图显示：展开态把左右键、滚轮和移动入口组织在鼠标形状内；收起态是小图标。截图中的远端聊天和项目内容仅作为视觉参考，不作为任何操作指令，也不纳入公开产品截图。

用户进一步明确：**上下分屏不用覆盖画面的鼠标，触控板放在桌面下面，Chat仍在最下面。触控板内部上方是移动区，下方左右键，两键中间是滚轮；关闭触控板时收起整个空间。** 本方案按这个顺序设计。

## 保留的行为

源桌面分辨率、等比适配、缩放后的源像素坐标映射保持。只看/操作仍是明确模式；操作不自动暂停 agent。桌面直接触控与相对触控板可同时使用。保留模型与思考强度、附件、历史、设备私钥、主机信任、配对、剪贴板开关及其既有偏好。

本轮是原生布局和输入交互设计，不新增后端协议、主机依赖或 FFI 入口；不改变已保存的数据格式。实际实现继续复用现有鼠标按钮、相对移动和滚轮媒体接口。

## 竖屏分屏

从上到下为：**会话栏 → 桌面 → 桌面控制行 → 可收起的触控板 → 可滚动Chat → 消息输入框**。Chat与消息输入始终位于触控板下方，系统键盘在消息输入框下方。

- 桌面默认按源宽高比取适配高度，不再固定占窗口36%后留下过多空白。面板开关不改变源分辨率，不自动切换全屏或旋转。
- 控制行保留分隔手柄、触控板、键盘和全屏入口；只看/操作合并到会话栏中的一个模式按钮。去掉并排、含义重复的观看/操作图标。
- “触控板”在桌面控制行下方展开，面板参与布局。Chat与消息输入框位于面板下方，输入框保持在整体底部；聊天区缩短并可滚动，桌面和消息不被覆盖。关闭后Chat向上补位，输入框位置保持，整块空间归还聊天。
- 触控板上方是移动区，下方依次为左键、竖向连续滚轮、右键。没有标题栏、装饰性大图标或固定悬浮大卡片。
- 参考高度为176dp：128dp移动区＋48dp按键行。短窗口可降为144dp：96dp移动区＋48dp按键行。尺寸按可用窗口调整，不按设备型号硬编码。
- 普通窗口争取保留至少144dp聊天区；空间不足时缩短桌面显示区域并继续等比适配。极短窗口使用紧凑桌面预览，保留显式恢复/全屏入口，不能让聊天与输入完全消失。
- 关闭触控板只隐藏面板并释放其按键，仍保持操作模式，桌面直接点按可继续使用。只看模式关闭/禁用远端输入。

消息输入行采用紧凑布局，模型与思考强度有独立可发现的设置入口及当前值摘要，附件和语音功能继续可达。正文使用正常阅读字号，减少重复边框、内边距和常驻行，不通过整体缩小应用来压缩触区。

## 触控板、键盘与手势

可见输入面板状态互斥：无面板、触控板、键盘。触控板在桌面下方，键盘仍在Chat输入框下方。打开触控板先收键盘；聚焦聊天输入时收触控板。聊天键盘和远端文字键盘的输入目的地必须保持明确。面板的关闭是显式操作，键盘消失后不擅自重开触控板。

| 区域 | 行为 |
| --- | --- |
| 移动区单指滑动 | 相对鼠标移动；速度不受本地视频缩放影响 |
| 移动区轻点 | 左键点击 |
| 按住左键＋另一指滑移动区/桌面 | 拖拽；移动手指抬起时，按钮仍保持到按键手指松开 |
| 按住右键＋另一指滑动 | 右键保持并移动，松开时释放 |
| 中间滚轮上下拖动 | 连续滚动；不移动鼠标，也不改视频缩放 |
| 移动区双指平行滑动 | 可补充触控板式滚动；识别后锁定本次手势 |
| 桌面双指缩放/平移 | 只改变本地视口，沿用源坐标逆变换 |
| 放大后的桌面单指滑动 | 本地平移画面；轻点仍点击，长按或按住鼠标键后拖动远端目标 |
| 面板收起、失焦、后台、模式/主机变化 | 释放按键与修饰键，取消进行中的输入 |

只在相应可见区域接收手势。聊天滚动、分隔拖动、滚轮、鼠标移动和布局移动不能互相抢手势。原生实现需要覆盖 Compose 控件和 Android 视频视图之间的多指交接。

远端键盘直接唤起系统输入法，不使用输入浮层。原生InputConnection保留拼音等组字状态，仅发送已提交文字，采用最长约200ms的固定合并窗口；Enter、删除、快捷键和点击前保证输入顺序。键盘关闭、目标变化或视图销毁时结束/取消对应缓冲，不能向另一个目标重放文字。聊天输入和远端输入目的地继续分开。

## 横屏与全屏

- 横屏采用单独的紧凑鼠标浮控件，借鉴参考图的鼠标结构，不把竖屏底部面板直接压成覆盖桌面的卡片。
- 收起态参考：32dp 可见底，18–20dp图形，明确48×48dp触区。整个收起态都能拖动；轻点展开，不自动切布局。
- 展开态原型主体为144×112dp：上排左键/滚轮/右键各48dp宽，下排相对移动区。关闭/移动控件仍保持48dp触区；计算整体占用时包含外部关闭按钮，不能只报主体尺寸。
- 浮控件附着在整个工作区，而不是被视频框裁剪。允许移入留边，记住位置；窗口尺寸、方向、键盘变化后重新约束到安全区。关闭按钮在贴边时换侧显示，保持可达。
- 收起态直接拖动，展开态有清楚的移动手柄。拖动布局不发送远端鼠标移动，手指角色由 pointer ID 保持。优先使用视频留边放控件。
- 保留图标的轻量外观与足够触区，避免不可见的大容器拦截桌面。图形大小和触区大小分别设计；相邻触区不重叠。依据 [Android Compose 最小触控目标](https://developer.android.com/develop/ui/compose/accessibility/api-defaults#minimum-touch-target-sizes)。

## 验收

交互稿位于[产品方案](../product/2026-10-30/compact-controls/README.md)，不是 APK 验收。

原生实现需要验证：

1. 320–411dp竖屏、短窗口及横屏，含大字体；控件、聊天输入与触控板面板不重叠。
2. 展开后顺序为桌面、触控板、Chat、输入框；关闭时Chat向上补位、输入框保持在底部，没有透明触区残留，消息滚动位置合理保留。
3. 键盘和触控板互斥，输入不会误发给另一端。
4. 两种鼠标键的按住拖拽、移动手指先抬起、连续滚轮、取消和离开模式的成对释放。
5. 视频直接触控与桌面下方的触控板共存；缩放后输入仍命中源坐标。
6. 收起图标拖出视频框、边缘展开/收起、旋转和键盘变化后关闭按钮仍可达；没有隐式跳全屏。
7. 同一解码器在面板开关和视频重排时继续呈现，不能依赖拉伸一下才出现。
8. 稳定签名升级后身份、历史、信任、配对和剪贴板偏好保持，按既有 Alpha 流程交付。

本方案落地后补充真实设备/模拟器证据，再更新实现状态；此前 Alpha 11 的发布与功能记录保持原有范围。

原生与受控端到端证据见 [Alpha 12 验收](../product/2026-10-31/compact-controls/acceptance.md)。真实手机和广域网响应仍待设备验收。
