# 多主机连接、排序与选中

Rust `ClientCore` 管理每台主机独立的 `AppCore` 工作区，共享设备密钥及同一个受锁保护的存储、会话簿和通知收件箱。连接意图保存为主机集合；首次使用读取原单主机意图，损坏的新意图文档不阻止初始化或触发网络操作。选中主机独立持久化，后台主机恢复不会抢走选中工作区。

主机切换只停止原桌面媒体；SSH、会话、资源和通知轮询继续运行。媒体启动、配对及接管验证选中主机，停止操作携带原主机身份。原生前台服务及系统推送注册根据全部连接维护。

会话排序默认使用创建时间，时间相同时按 ID 确定顺序。其他选项为创建时间升序、最近活动和标题。排序按主机保存，不改变选中项及运行状态。归档或删除选中项时使用操作前顺序，优先后继、其次前驱；归档成功立即更新列表并展示后继缓存。打开、归档、恢复、创建、删除命令均绑定主机 ID，会话列表行使用主机和会话组成的身份。

## 验证

- 本地受控 SSH peers：两台机器同时连接，反复切换不更换连接对象；后台主机掉线只恢复自身；缓慢的第三台握手可选择及取消，不阻塞已有连接，也不因重复点击重启。选中离线机器时重建客户端，只恢复仍保留意图的后台机器；全部断开清除全部意图。
- 相同会话 ID 的不同主机：延后执行的打开操作保持原目标；各自的选中项及排序可重建恢复，未知主机命令失败。
- 会话回归：活动时间变化、归档和输入记录重排不改变默认创建顺序；显式最近活动排序及相同时间的稳定次序；归档/删除按旧位置选择邻居，归档立即更新列表和后继缓存，操作非选中项保留选择；过期 catalog 不覆盖新状态。
- `cargo test --workspace --locked`、Rust clippy、Android Release JVM tests、Release lint，以及 Debug instrumentation 源码编译。设备执行和 Mac/iOS 的 Xcode 执行单独记录，不以编译代替运行验收。

发布包以 Alpha 81 GitHub prerelease 的附件、源码提交和校验清单为准。本次不重启用户主机服务，不发送模型任务。
