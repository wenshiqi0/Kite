# Friendly skill names and summaries

The Skills picker uses `interface.displayName` and `interface.shortDescription` from Codex instead of presenting plugin-qualified machine identifiers and model trigger instructions as the main label and description. The shared Rust catalog retains these optional fields, prefers the interface summary over the protocol's legacy `shortDescription`, and orders the catalog by its display title. Blank metadata falls back to the original name/description. Android applies the same title to selected chips and accessibility labels, and searches both display metadata and the original fields. Native skill inputs still send the original machine name and path.

141 Rust tests, all-target Clippy, 70 Release JVM tests, Release lint and instrumentation source compilation passed. The added protocol regression covers interface metadata, null/missing/blank fields, legacy summary fallback and friendly-title ordering; the existing turn-input regression now includes a distinct display title and still requires the original invocation. A real local Codex app-server loaded three temporary project fixtures and returned the expected display fields without a model turn; this is a protocol-loader check, not evidence that the fresh isolated server exposed the user's installed Adobe plugins. [Wire results](live-skill-metadata.json).

Three native API 36 x86_64 tests passed against source `6cd20b0a88dd5430cd4ce567a6355cafbbfcef28`: the three plugin-style skill titles and summaries are visible without internal IDs or trigger instructions; a title-only search, selection, removable chips and legacy fallback work; and loading/empty/error states remain distinct. [Native results](native-validation.json), [actual picker screenshot](skills-friendly-names.png). The owned debug harness uses matching Rust and regenerated UniFFI bindings, with the previously documented explicit NDK compiler-rt linkage for x86_64. Its container has no network access and uses a read-only AVD overlay. These results do not claim a physical-phone installation or execution of the public ARM64 package. No model turn, global skill configuration change or host service upgrade was performed.
