# Simple session initialization and submit lock

New-session creation, process startup and Codex chat setup share one presentation phase: **正在初始化会话…**. While creating, the previous conversation, old draft contents and old title are hidden; initial empty sessions show one centered notice instead of history/loading/terminal hints. Header history indicators and repeated footer notices are suppressed. Existing history remains readable during later reconnections, with one initialization notice. Startup failure replaces the loading notice with a brief error and retry action; real failure state is retained.

Only READY can submit. The editor and compose controls are disabled during initialization. Both native prompt entry points check the lock immediately and recheck it before dispatch, including the selected agent ID; rejected submissions keep the draft and attachments. Rust independently rejects a launch-pending agent or selected Codex session whose composer is not ready, before creating input or invoking transport. A creation request cannot temporarily inherit the old ready session's submit capability.

140 Rust tests, all-target Clippy, 68 Release JVM tests, instrumentation compilation and Release lint pass. Three JVM scenario tests cover old-session creation, launch/backend transitions, failure and disconnection. A Rust transport-readiness regression covers both startup gates and readiness. Three native API 36 tests cover the initialization/failure screens, a disabled editor's rejection of text edits, one retry action, the icon-only latest control and paired questions. Accessibility checks search visible nodes and attempt editing actions rather than mistaking an informational ancestor's enabled flag for editor capability. [Results](validation.json), [initialization](session-initialization.png), [failure and retry](session-initialization-failure.png).

The prior icon-only action and atomic echo merge are included from immutable [Alpha 40](https://github.com/wenshiqi0/Kite/releases/tag/v0.2.0-alpha.40); this additional work is delivered in Alpha 41 / versionCode 43. Native execution uses an owned x86_64 debug harness, with matching Rust/bindings and explicit NDK compiler-rt linkage, and does not claim a physical-handset install of the public ARM64 package. No real model request or host upgrade was performed.
