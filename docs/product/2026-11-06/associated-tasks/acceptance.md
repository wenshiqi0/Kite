# Android associated tasks

This change is stacked on [PR #18](https://github.com/wenshiqi0/Kite/pull/18), commit `ca53a8bcfea870fd34ed785fbe2c048dda1b7cff`, already published as Alpha 85. The independent PR targets that branch so its diff contains only this optimization. No other PR is merged.

Android presents **关联任务** as a flat, bounded list with task titles and the original executor metadata. Provider IDs and source edges remain unchanged; Rust still validates the host, original conversation and full recorded descendant chain before reading history. No owner, resume, prompt or conversation-selection operation is added.

The entry retains a 48dp touch height. The drawer starts folded, including the selected conversation; search can expand it. Expanded rows occupy at most 96dp with their header outside the scroller. The main workspace no longer wraps this list in another vertical scroller. Details use 68% of workspace height, bounded to 320–560dp and the available height. The fixed content allocation includes bottom safe padding and the drag handle, leaving the sheet's full-window anchor constraints intact.

Material3 1.4.0 forwards residual list fling velocity to sheet settlement even at the expanded anchor. The inspector consumes only the remaining **upward** velocity after inner tool lists and history have scrolled. Downward scrolling, handle dragging and swipe dismissal remain enabled. Offset-dependent top insets cannot resize this sheet. Initial history positioning runs once; refresh retains the current message and offset.

Eight native Android 16/API 36 tests executed successfully on an isolated x86_64 emulator with production Kotlin and matching Rust/UniFFI. They cover flat targets from different provider depths, compact touch/list bounds, all rows being reachable, public messages, tool arguments/output, final results, refresh, return to the original conversation, direct and nested fast flings, downward handle dismissal, and the actual workspace tail follower. Gestures inject six moves spaced 4ms apart and lift immediately. Direct flings retain the same sheet position across 300 samples; nested-tool and workspace flings each retain their position across 100 samples. Refresh retains the same message at **941px** before and after reading an appended result. [Numeric evidence](native-validation.json), [compact entry](compact-entry.png), [settled details](readonly-details.png).

Source checks: **83 Release JVM tests**, Release lint, **3 Rust read-authorization tests**, **9 publisher tests**, and native test compilation pass. Obsolete tree-collapse JVM/native cases are replaced by the executed flat-task interaction checks; gesture and position assertions remain strict.

The baseline's ordinary fling rebounded by up to 36px and settled. A higher-velocity control using the original inspector failed while its moving title became briefly unavailable to accessibility; its failure screenshot shows the sheet displaced toward the status bar. This is evidence of the residual-velocity path, **not a claim that the reported endless handset oscillation was reproduced verbatim**. Physical-handset acceptance and real-host interaction remain separate. No macOS source is changed; the known baseline `LiveClientTests.swift` migration failure is outside this Android task.

Delivery uses [Alpha 86](https://github.com/wenshiqi0/Kite/releases/tag/v0.2.0-alpha.86), versionCode **88**, via `android/scripts/release-alpha.py`. The tagged workflow and release manifest identify the signed ARM64 source and assets. Runtime emulator checks and public-package checks are separate evidence. The host interface is unchanged from Alpha 85, so this optimization needs only the Android client update.
