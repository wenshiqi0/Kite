# Implementation stages — 2026-11-01

The user authorized staged implementation, retaining existing history, host trust, device identities and pairing. Desktop backend migration targets herdr-core evaluation first; no production Herdr TUI session is replaced before restoration is validated.

The desktop product has **both client and host roles** on Linux and macOS. A desktop must connect to other desktop machines for sessions, Chat and remote desktop use while keeping its own host services available. The delivered host panel is one stage of that product. See the [desktop scope](desktop.md) and [RFC 0015](rfcs/0015-desktop-client-and-host.md).

5. **Multi-machine MCP (pending; host-local stdio queries available):** machine/session identity, explicit tool targets, durable work/messages/results and artifact references, local stdio integration and authenticated peer transport. MCP exposes the operations; task delivery, restoration and input ownership are application state. A desktop client connection does not by itself complete agent-to-agent messaging.
6. **Rich content expansion (pending):** shared semantic message blocks with native renderers for prose, command/log/diff, images/files and citations; streaming partial markup; formulas/diagrams after baseline content coverage. Keep command text exact and do not execute model HTML.

7. **Agent notifications (Alpha 28, system-push deployment pending):** independent bounded host journal/checkpoints, durable mobile cursor/inbox, system channels/permission/switch, verified target navigation and private FCM registration/sender/retry. Source and connected-notification tests pass. Actual newly delivered post-reclamation FCM and configured handset acceptance remain outstanding; see [RFC 0017](rfcs/0017-agent-notifications.md).

Current facts: one active SSH connection is held by mobile AppCore; Linux Kite Node now owns the host bridge and local lifecycle policy. Capture discovery still uses Linux `/proc`. The host panel does not establish a full desktop remote client or durable multi-node orchestration. Upstream herdr-core and Herdr TUI are separate servers with no automatic shared agents. Sunshine's macOS host support is marked experimental upstream; screen capture/input must be validated on both target platforms.
