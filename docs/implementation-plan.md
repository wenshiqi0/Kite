# Implementation stages — 2026-10-31

The user authorized staged implementation, retaining existing history, host trust, device identities and pairing. Desktop backend migration targets herdr-core evaluation first; no production Herdr TUI session is replaced before restoration is validated.

Delivery recorded here: [0.2.0-alpha.16](https://github.com/wenshiqi0/Kite/releases/tag/v0.2.0-alpha.16), Android versionCode **18**, published as a GitHub prerelease. Its [publication evidence](product/2026-10-31/attachments-only-menu/published-release.json) records the exact source, checksum, passing main/tag CI and in-place installation with profiles, identity, trust, pairing, catalogue and 12 complete-cache files retained. The public APK's composer add menu contains only image/file/audio resources; desktop navigation remains available separately. An explicit skill picker is not implemented. Alpha 15's [control/card acceptance](product/2026-10-31/compact-mouse-and-hosts/acceptance.md) and Alpha 13's [complete-history acceptance](product/2026-10-31/complete-transcript/acceptance.md) retain their original runtime scopes. Physical-phone motor strength and WAN responsiveness remain separate acceptance work.

1. **Android experience (Alpha 16 delivered):** complete independently synchronized conversations, per-session full caches and versioned message edits; local virtual rendering with one screen ahead / half a screen behind; no history network loading or data eviction on scroll. Fullscreen uses a compact mouse and explicit arrow hotspot, synchronized buttons/wheel, tactile feedback and the right-hand rail; the trackpad is limited to portrait split view. Host cards show connection state and primary actions, with configuration and diagnostics available separately. A consistent dark palette covers Compose and native rich content. [Control/card acceptance](product/2026-10-31/compact-mouse-and-hosts/acceptance.md), [pointer correction](product/2026-10-31/virtual-pointer/acceptance.md), [complete-history acceptance](product/2026-10-31/complete-transcript/acceptance.md) and [RFC 0013](rfcs/0013-complete-transcript-and-dark-workspace.md). Alpha 12's prior [publication record](product/2026-10-31/compact-controls/published-release.json) remains historical. Direct system IME, source-resolution mapping, session questions/approvals and the one-switch text clipboard remain supported. Desktop audio and image/file clipboard formats are still pending.
2. **herdr-core migration experiment (restoration feasibility verified):** isolated herdr-core 0.1.14 reattached the same disposable Codex thread, displayed its old history, and the model recalled the previous token. A follow-up stopped the old owner and repeated restoration with a fresh provider process without legacy pane environment; JSON-RPC confirmed the original thread ID. [Recorded result](product/2026-10-30/herdr-core-migration.md). Production remains on Herdr TUI. Runtime-independent identity/routing, questions/approvals, automatic recovery and full archive/restore still need validation before a migration RFC is accepted.
3. **macOS/Linux desktop nodes (pending):** client UI plus managed Sunshine and agent runtime; platform display/input/clipboard/process adapters; GUI shutdown independent of host services; preserve external user-owned services.
4. **Multi-machine MCP (pending):** machine/session identity, explicit tool targets, durable work/messages/results and artifact references, local stdio integration and authenticated peer transport. MCP exposes the operations; task delivery, restoration and input ownership are application state.
5. **Rich content expansion (pending):** shared semantic message blocks with native renderers for prose, command/log/diff, images/files and citations; streaming partial markup; formulas/diagrams after baseline content coverage. Keep command text exact and do not execute model HTML.

Current facts: one active SSH connection is held by AppCore; the host adapter uses Linux `/proc`. Neither is a complete desktop/multi-node implementation. Upstream herdr-core and Herdr TUI are separate servers with no automatic shared agents. Sunshine's macOS host support is marked experimental upstream; screen capture/input must be validated on both target platforms.
