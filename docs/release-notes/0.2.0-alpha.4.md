# Kite 0.2.0-alpha.4

Fixes mobile connection and desktop operation dead ends reported during phone testing.

- Connection settings remain visible until SSH and herdr actually connect. Stages, immediate failure reasons and a Copy diagnostics action explain failures.
- Connecting the host automatically reuses its agent. When none exists, Kite prepares a persistent default Codex session in the host user's home directory; reconnecting reuses it. Extra project sessions are optional. Terminal arrows, Enter, Esc and Tab support first-run choices. Host Codex installation / sign-in is still required once; no model task is submitted automatically.
- Clear Watch / Operate modes. Both support local zoom / pan while keeping the host resolution. Source desktop pixels are shared by the render transform, inverse direct-touch mapping and relative motion scale.
- Explicit portrait / landscape controls work independently of system auto-rotation. Fullscreen opens landscape on phones.
- Trackpad tap, double-tap / hold drag, two-finger right-click / scroll and pinch zoom; explicit left / right buttons and Move view. A pinch cannot simultaneously click or scroll the host.
- Existing device keys, host trust and Sunshine pairing are retained; agent pause stays separate from desktop operation.

Validation: Rust and publisher regression suites, seven Android viewport unit tests, Android Release build / lint / unit tests in CI, iOS simulator compilation, and API 36 ARM64 emulator gestures through real Linux SSH / herdr / Sunshine. A zoomed / panned touch was observed at the exact expected source point (1100, 600). Desktop and terminal-choice acceptance use labelled controlled fixtures; backend acceptance also verifies a real Codex reply to a benign no-tools connectivity prompt.

Limits: ARM64 Android, Chinese interface, Linux X11 host discovery, no audio or iOS desktop player. Provider login and initial setup can require additional interaction. A real default Codex reply and same-session reconnect were also verified on the host. Emulator / LAN tests do not establish physical-phone or WAN performance.
